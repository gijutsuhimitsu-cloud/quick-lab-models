# モデルの置き方と決まり

このリポジトリには、軽くて速い予測モデルを何個でも足していきます。どのモデルも同じ形にそろえるので、1 つ使えたら全部使えます。

*English: every model folder follows the same layout and rules below, so once you know one model you know them all.*

## フォルダの形

```
models/<モデルの名前>/
  README.md        何を予測するか・使い方（ブラウザ・Node）・精度の要点・向かない物
  MODEL_CARD.md    精度・評価の仕方・データ・分かっている弱点
  ATTRIBUTION.md   出典（データごとに：作者・配布元・DOI・ライセンス・こちらで変えたこと）
  LICENSES/        同梱が要るライセンスの原文（Apache 2.0・BSD など）
  js/              推論のプログラム（MIT）。ビルドなしで <script> でも require でも読める
  weights/         学習済みの重みと小さな表（CC BY 4.0）。JSON か CSV
  examples/        いちばん短い使い方（ブラウザの 1 枚と、Node の例）
  tests/           JavaScript の予測が、学習側（Python）の予測と合うかの照合
  train/           学習し直す道具（MIT）
    README.md      手順（必要な物・時間・コマンド）
    OWN_DATA.md    自社のデータの形と、足し方
    own_data/      自社のデータの置き場。.gitignore でリポジトリに入らない
```

## 決まり

1. **データは、商用で使えて継承のない物だけ**：CC0・CC BY・Apache 2.0・MIT・BSD など。非営利限定（NC）・改変禁止（ND）・継承（SA）・「研究用のみ」・出所が分からない物は使いません。
   - 配布元のライセンスの欄で確かめて、`ATTRIBUTION.md` に書きます。
   - データセット全体のライセンスの表示と、中の行ごとの出所が違うことがあります（例：集めたデータの中に、会社のカタログや非営利のデータベースから写した行がある）。行の出所も見て、怪しい行は外します。
2. **特定の会社の製品名を出さない・装置に似せない**（例：カラムは「C18 No.3」のような一般名）。
3. **推論はブラウザで軽く**：1 回の予測はミリ秒以下を目安に、重みは gzip で数 MB まで。サーバーには何も送りません。
4. **予測には幅（確かさの目安）を付けます**。当たらない物を、当たりそうに見せないためです。
5. **重みと学習の道具を一緒に出します**。同じ手順で作り直せること、自社のデータを足して学習し直せることが条件です。（例外：`solubility-ensemble` は推論と重みだけで、学び直しの道具はまだ入っていません。学び直しは同じ対象の `solubility` を使います。）
6. **pickle のような、読み込むだけでプログラムが動く形式では配りません**（JSON・CSV・数値だけのバイナリ）。
7. 個人の環境のパス（`C:\Users\…` など）を書きません。Python と Node の場所は、環境変数か引数で渡します。
8. 版の番号は、重みのファイルの `meta.version` と README の表をそろえます。

## ライセンスの付け方

- プログラム（`js/`・`train/`・`tests/`・`examples/`）：MIT（リポジトリの直下の `LICENSE`）
- 重み・表（`weights/`）、学習の表（`train/base_data/`）、照合用の値（`tests/` の JSON）：CC BY 4.0（`LICENSE-DATA.md`）。中身の出典は各モデルの `ATTRIBUTION.md`
- 元のデータ：それぞれの元のライセンスのまま（Apache 2.0 のデータは、その全文を各モデルの `LICENSES/` に）
- 同梱した第三者の物（RDKit.js と、その中の部品）：それぞれの元のライセンス（`vendor/rdkit/`）。新しい部品を同梱する時は、中に入っている部品のライセンスも確かめる
